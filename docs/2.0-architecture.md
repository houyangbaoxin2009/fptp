# FPTP Osiris 2.0 — 架构蓝图

> 目标：打造**替代 Photoshop 级别的专业图像编辑软件**（Windows，单机离线，插件生态）。
> 代号 osiris，与 1.x（证件照工具，master 分支）完全隔离，从零开始。
> **核心理念（用户定调）：整个应用完全可编辑——只提供加载模组的框架与底层，其余全部由模组提供。内置我们做好的官方模组。**
> 可扩展性是第一设计原则：一切皆插件（含 UI），契约语言无关（为 Leibniz 预留）。

## 0. 工作台模型（模组化工作台，VS Code 模式）⭐ 用户定调

```
┌─────────────────────────────────────────────────┐
│  壳 (Osiris.App.Workbench) —— 极薄              │
│  · 只提供：模组加载框架、工作区容器、命令总线    │
│  · 不内置任何业务功能、不硬编码任何 UI           │
├─────────────────────────────────────────────────┤
│  模组 (Module) —— 一切功能皆模组                 │
│  · 菜单项 / 工具栏按钮 / 面板 / 命令             │
│  · 滤镜 / 工具 / 格式 / 工作流（证件照流程等）   │
│  · 官方模组与第三方模组完全同级                  │
└─────────────────────────────────────────────────┘
```

**核心原则**：
1. **壳零业务**：Workbench 只渲染模组注册的 UI（菜单/工具栏/面板），自身不含任何功能逻辑
2. **命令总线**：所有动作走 `ICommand`（Id + Execute + CanExecute），UI 元素只绑定命令 Id，不直接调逻辑
3. **UI 契约纯净**：`Ui` 契约在 Core 中定义（纯数据，无 WinForms 依赖），壳负责映射到 WinForms 控件
4. **内置官方模组**：我们做的功能（证件照流程、基础滤镜）作为 `Fptp.Plugins.Builtin` 模组提供，与第三方同级
5. **一切皆模组**：滤镜/工具/格式/UI 贡献/工作流统一走模组管线

**模组可贡献的 UI 资源**：
- `MenuContribution`：菜单项（路径 + 命令 Id + 快捷键）
- `ToolbarContribution`：工具栏按钮（命令 Id + 图标）
- `PanelContribution`：停靠面板（图层面板/历史面板/属性面板等）
- `StatusContribution`：状态栏条目

## 1. 定位与范围

### 1.1 终极目标（长期）
- 专业级图像编辑器：图层、蒙版、选区、滤镜、混合模式、色彩管理、批处理
- 插件生态：用户可编写滤镜 / 工具 / 导入导出格式插件
- 脚本化：自创语言 **Leibniz**（设计阶段）未来作为插件/脚本语言接入，与宿主语言无关的契约

### 1.2 阶段划分
| 阶段 | 内容 | 里程碑 |
|---|---|---|
| **M0 骨架** | 解决方案结构、文档模型、渲染管线、插件宿主、核心契约 | 空编辑器可运行，可加载图片，可枚举插件 |
| **M1 编辑** | 图层栈、撤销/重做、选区、基础滤镜（含 1.x 证件照能力作为首批工具） | 能完成 1.x 全部证件照流程 |
| **M2 专业** | 蒙版、混合模式、笔刷、色彩管理、通道 | 达到轻量 PS 编辑能力 |
| **M3 生态** | Leibniz 脚本桥、插件市场、批处理自动化 | 插件开发者可第三方开发 |

### 1.3 技术栈（Oracle 已验证 ✅）
- 运行时：**.NET 10 为主 + net48 多目标**（Win7 兼容硬要求）；共享层用 **netstandard2.0** 做最大公约数
- UI 壳：Windows Forms（Win7 兼容前提下的务实选择）
- 渲染：**SkiaSharp 2.88.9 全目标统一**（3.x 启用 DX12，Win7 有风险；锁 2.88 保证 Win7 可靠 + 单一 API 面）
- 配置：JSON 即时持久化（沿用 1.x 习惯）

依赖方向（单向）：`App/Cli → PluginHost → Contracts(Core)`；`App → Core`；`Engine.Skia → Core`；插件 → Core 公开 API。

## 3. 文档模型与像素存储（Oracle 验证 ✅）

```
OsirisDocument
├── Width / Height / ColorSpace（Srgb8，预留 Rgb16Linear）
├── Layers : IReadOnlyList<Layer>
└── History : HistoryStack

Layer
├── Name / Visible / Opacity / BlendMode
├── Mask（可选，同尺寸 8bit + Enabled/Locked）
├── OffsetX / OffsetY / Transform（未来）
└── Pixels : PixelSurface          ← 像素真相源（非 SKBitmap！）

PixelSurface（核心存储决策）
├── byte[] BGRA 预乘 8bit
├── Span<byte> 直接访问（net48 经 System.Memory 包）
├── ArrayPool 临时缓冲（滤镜重负载防 GC 压力）
└── 渲染时零拷贝 SKImage 视图（SKImage.FromPixels）
    ✗ 否决 SKBitmap 为源：非托管所有权、无法池化、resize 重分配
    ✗ 否决不可变缓冲：交互编辑内存翻倍

IUndoableCommand { Name; Execute(ctx); Undo(ctx); Redo(ctx); }
HistoryStack：线性撤销/重做栈，内存上限，像素命令记录区域快照（非整图）
预留：参数化非破坏调整层（v2 smart filter，图节点式历史）
```

## 4. 插件契约（Oracle 验证 ✅ — 契约不泄漏 SkiaSharp）

```csharp
// Osiris.Core.Plugins —— 插件与脚本共用同一契约
public interface IPlugin
{
    string Id { get; }
    string Name { get; }
    string Version { get; }
    string MinHostVersion { get; }
    void Initialize(IHostContext host);
}

public interface IHostContext        // 真正的"宿主桥"：插件与 Leibniz 脚本共用
{
    OsirisDocument ActiveDocument { get; }
    IPluginRegistry Plugins { get; }
    IProgress Progress { get; }
    CancellationToken Cancellation { get; }
    IUiService Ui { get; }           // UI 服务：贡献菜单/工具栏/面板/激活工具（无 UI 宿主为 null）
    IServiceRegistry Services { get; }  // 服务注册表：模组间互相调用（见下）
}

public interface IFilterPlugin : IPlugin
{
    IEnumerable<IFilterProcessor> Filters { get; }
}

public interface IFilterProcessor    // 滤镜契约：PixelSurface 进，PixelSurface 出
{
    string Id { get; }
    FilterParameters Defaults { get; }
    PixelSurface Apply(PixelSurface input, FilterParameters p,
                       IProgress progress, CancellationToken ct);
    // 引擎内部三层：SkSL 源码(GPU) | CPU 委托 | 内置快速路径
}

// ---- 交互工具契约（套索/画笔/选框等）：壳只路由事件，工具自绘覆盖层 ----
public interface IEditorTool : IPlugin
{
    void Activate();  void Deactivate();
    void MouseDown(ToolMouseEvent e);   // 纯数据事件（画布像素坐标+按钮+修饰键）
    void MouseMove(ToolMouseEvent e);   // 零 UI 依赖：CLI/脚本亦可激活
    void MouseUp(ToolMouseEvent e);
    void DrawOverlay(IToolOverlay overlay);  // 蚂蚁线等覆盖层自绘
}

// ---- 模组间互相调用（服务注册表）----
// 模组 A 在 Initialize 注册服务实例（按接口），模组 B 经 host.Services.Get<T>() 获取调用。
// 解耦：调用方只依赖 Core 接口契约，不依赖具体模组程序集（按需加载/卸载不受牵连）。
public interface IServiceRegistry
{
    void Register<T>(T service) where T : class;   // 同类型重复注册则覆盖
    T Get<T>() where T : class;                    // 未注册返回 null
}

public interface IDocumentImporter : IPlugin { ... }  // 编解码
public interface IDocumentExporter : IPlugin { ... }
```

**Leibniz 接入点**：FilterParameters 声明式自描述（参数元数据），v1 Leibniz AST 解释执行调用同一 IHostContext；v2 编译到 SkSL 走 GPU。契约零语言依赖。

## 5. 多目标兼容策略（Oracle 验证 ✅）

- **三项目结构**：Core/Engine.Skia → netstandard2.0（最大公约数）；App → `net48;net10.0-windows` 双目标
- `#if NETFRAMEWORK` 仅出现在 ≤3 处：插件加载器、启动引导/DPI、个别 API 差异
- **插件加载器**（唯一条件编译区）：
  - net10：`AssemblyLoadContext`（IsCollectible=true）+ Resolving 转发共享程序集（SkiaSharp/Osiris.Core/System.*）到默认 ALC → 支持卸载
  - net48：`Assembly.LoadFrom` + 插件目录探测，无卸载（重启生效），**否决 AppDomain**（MarshalByRefObject 税，图像数据跨域不可行）
- System.Drawing 仅作 WinForms 胶水（BackColor/图标/PrintDocument），**绝不作为像素引擎**
- SkiaSharp 2.88.9 兼容 netstandard2.0 → net48 + net10 同一 API 面；native skia.dll 随包分发

## 6. 滤镜管线分层（Oracle 验证 ✅）

```
L0 合成层    — skia 内置 BlendMode + 蒙版 + 不透明度（SKPaint，非滤镜）
L1 快速路径  — 常见滤镜映射 SKColorFilter(颜色矩阵) / SKImageFilter(模糊等)
L2 统一契约  — IFilterProcessor：GPU(SKRuntimeEffect/SkSL) 或 CPU(Parallel.For+Span)
L3 脚本桥    — Leibniz AST → 同一 IFilterProcessor 契约；v2 编译 SkSL
L4 推理层    — NPU/GPU 神经网络推理（ONNX Runtime + DirectML），见第 7 章
关键：插件/脚本只碰 PixelSurface，SkiaSharp 是 Engine 内部实现细节
```

## 7. NPU / 协处理器推理层（L4）— AI 滤镜（用户定调 ✅）

> 定位：AI 滤镜（超分辨率/降噪/去模糊/抠图/风格迁移）作为**可选的 L4 推理层**，
> 对 Core **零侵入**——Core 不知道 NPU 存在，一切通过既有滤镜契约与模组管线。

### 7.1 核心决策

| 决策 | 方案 | 理由 |
|---|---|---|
| 推理引擎 | **ONNX Runtime**（netstandard2.0 兼容 Core 目标） | 跨平台统一 EP：Win=DirectML / Linux=OpenVINO / macOS=CoreML / Android=NNAPI，与跨平台路线一致 |
| 硬件加速 | DirectML 统一 GPU+NPU，**同一份代码自动用** | Intel AI Boost / AMD Ryzen AI / Snapdragon X 无需逐芯片适配 |
| 能力探测 | 运行时探测 EP 可用性，**NPU→GPU→CPU 自动降级** | 无 NPU 机器照常跑（Win7 无 NPU，走 CPU/GPU 路径） |
| 交互策略 | AI 滤镜=一次性全图应用；预览用**小尺寸缩略图**推理 | NPU 推理也要几十~几百 ms，大图实时推理不可行（PS Neural Filters 成熟做法） |
| 依赖分发 | AI 模组自带 ONNX Runtime native 库（约 30~50MB） | 独立模组包，不需要 AI 的用户不背这个体积 |

### 7.2 架构原则

1. **AI 滤镜 = 普通滤镜模组**：实现 `IFilterProcessor` 契约（PixelSurface 进/出），贡献菜单+命令走既有命令总线——模组内部用 ONNX Runtime 做推理，壳与 Core 无感知
2. **L4 是可选层**：非 AI 滤镜管线完全不经过推理层；未安装 AI 模组的系统行为与今天完全一致
3. **推理会话托管在模组内**：模型加载延迟（首次 1~2 秒）与显存/NPU 内存由模组管理，用 `IHostContext` 的进度与取消令牌对接 UI
4. **模型文件即资源**：`.onnx` 模型随模组包分发，用户可替换/新增模型（延续"配置即文件"哲学）
5. **Win7 约束**：NPU 是 Win10/11 + 新硬件时代产物，Win7 目标下 AI 滤镜自动降级 CPU/GPU——功能可用，性能受限，由能力探测兜底

### 7.3 与既有分层的关系

```
L0-L3：确定性算法（灰度/模糊/曲线/混合）→ 永远走 CPU/GPU 快速路径
L4：   学习型算法（超分/降噪/去模糊/抠图）→ 需要时经 ONNX Runtime 推理
同一 IFilterProcessor 契约，两种实现，调用方无差别
```

## 8. 关键设计原则

1. **UI 与核心完全解耦**：Osiris.Core 无任何 WinForms/SkiaSharp 依赖，可单元测试、可跨平台
2. **插件 = 一等公民**：一切可扩展点（滤镜/工具/格式/主题）走契约，内置功能也是插件
3. **命令模式**：所有修改走 IUndoableCommand，撤销重做为内置能力
4. **像素缓冲自有**：PixelSurface 独立于渲染后端，插件不接触 GDI+/Skia 对象
5. **契约语言无关**：声明式元数据自描述，Leibniz 脚本与 C# 插件同一加载管线
6. **配置即文件**：JSON 即时持久化（沿用 1.x 用户习惯）
